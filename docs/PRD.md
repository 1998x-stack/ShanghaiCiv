## 0. 执行摘要

ShanghaiCiv 通过真实地理边界、统一六边形空间索引、可追溯的统计数据和程序化地图艺术，为用户提供一个既像策略游戏地图、又具备严肃数据分析能力的上海探索系统。核心输出不是「把上海变成游戏」的模拟数值，而是 **以视觉语言降低理解城市空间、区际差异与产业结构的门槛**。

### 0.1 交付定义

MVP 应使用户能够：

1. 在授权且符合适用地图要求的底图/地图表现上浏览上海全部 **16 个区**，包括崇明及其他相关岛屿；
2. 平移、缩放、搜索并选中区、重点区域或地理格网；
3. 查看人口、面积、GDP、产业结构等**真实可用且标注口径**的数据；
4. 切换至少 **4 个通过数据与合规门禁的专题图层**；不足时不以伪数据凑数，发布门槛相应进入阻塞评审；
5. 点击数值查看发布机构、引用文件、时间范围、统计单位、空间粒度和缺失/估计说明；
6. 使用可复现的数据构建流程和自动质量检查生成可部署静态站点；
7. 在 GitHub Pages 上看到通过技术和地图发布门禁的公开版本；未通过时只提供本地/受控预览。

### 0.2 产品成功标准（首版目标，非既有成果）

| 指标 | 目标 | 验证方法 |
|---|---|---|
| 行政区覆盖 | 16/16 区名称、区划代码和几何引用可核对 | 规范化数据校验 + 人工对照 |
| 数值来源完整度 | 所有展示的正式统计数值均有来源与统计期 | schema 校验及随机抽样 |
| 误导性空间细化 | 0 项：不能把区级数据伪称 1 km 格网实测 | 规则断言及界面审查 |

| 地图与数据发布 | 合规负责人逐项签署发布准入 | 发布门禁清单 |
| 基础使用体验 | 桌面及常见移动视口可操作，键盘基本可达 | E2E + 人工检查 |

## 1. 背景与问题

### 1.1 用户问题

- 传统上海统计年鉴/公报分散在多机构、多格式和多年度中，空间关系不直观；
- 常规在线地图善于导航，却不善于解释「为什么陆家嘴是金融节点、张江为何形成科技产业集聚、临港与虹桥承担何种经济与交通功能」；
- 区级统计、街镇数据、园区和 POI 的时间与地理粒度不同，未经统一建模容易产生看似精确、实则误导的图层；
- 可视化网页往往缺乏来源、复现步骤、数据版本和质量守门机制。

### 1.2 机会

从 USACIV 学习「数据源→规范化中间结果→空间 Builder→可部署 JSON→Canvas 渲染→Almanac」的体系，同时根据上海数据可得性、地图测绘合规及城市空间尺度重新设计。

### 1.3 非目标（MVP）

- 不提供实时交通导航、出行路径或实时人口；
- 不把区 GDP 按面积平均分给格网，或声称街镇/网格级产业产值未经官方披露；
- 不做土地开发/军事/敏感设施推断，不处理个人轨迹或个人信息；
- 不做回合制模拟、城市建设、多人对战、LLM 自动决策；
- 不在确认许可前抓取商业 POI、复制商业瓦片或公开再分发受限地理数据；
- 不因视觉效果而改变行政区边界或对公众展示未经审核的地图内容。

## 4. 数据模型与权威边界

### 4.1 空间实体

- `Municipality`：上海市（市级指标）。
- `District`：16 个区；以官方标准区划编码和已授权行政界线为准。
- `Subdistrict/Town`：街道、镇、乡，只有取得合法边界及对应统计口径才进入正式图层。
- `Zone`：陆家嘴、张江、虹桥、临港等功能区域，边界可能由多份规划确定，必须记录边界版本和覆盖关系；首版允许仅以**代表性点位**定位。
- `HexCell`：1 km 候选半径的空间索引单元（中心至顶点）；用于地形/区域查询/空间关联，不天然具有 GDP/人口。
- `Facility`：有合法公开许可的港口、交通、文化等设施点/线；不纳入敏感地理要素。

### 4.2 坐标与精度

所有输入保留**原始 CRS、坐标来源和精度**；构建阶段采用经专业确认的适合上海的米制投影处理，输出统一的地图平面坐标。与在线地图服务交互时明确坐标系转换要求及授权条件，禁止未经核验混用 WGS84、CGCS2000、GCJ-02、BD-09。

候选网格为尖顶六边形（pointy top）、odd-r 偏移布局，半径 R=1,000 m，单格面积约 `(3√3/2)R²≈2.598 km²`。正式范围、原点、网格行列及水陆掩膜由已授权边界计算，**不得从面积直接臆造格子数量**。

### 4.3 统计数据的空间真实性

| 指标原始粒度 | 地图展示规则 | 禁止操作 |
|---|---|---|
| 市级 | 全市顶部指标与市域统一说明 | 作为每区/每格真实测量值 |
| 区级 | 区界专题填色、区面板、比较榜单 | 均匀拆给格网冒充实测 |
| 街镇级 | 有边界且许可允许时填色及面板 | 以街镇名称猜边界 |
| 设施点级 | 精度和许可满足时绘制点位 | 将设备位置推断为产能或安全信息 |
| 遥感格网 | 按数据许可、像元质量和分类规则聚合到六边形 | 声称分类一定代表法定用途 |
| 估计/模型推断 | 可用独立视觉层，标记「估计」及方法/不确定性 | 与官方观察值混用同一图例 |

每个数值都有 `value`、`unit`、`period`、`geography_id`、`granularity`、`source_id`、`status`（observed/derived/estimated/unavailable）、`method_id`、`quality_flags`。**未知必须是 null，不能默认 0。**

### 4.4 官方数据优先级与版本

1. 上海市统计局年鉴与统计公报，留意统计期、修订口径和公报发布时间；
2. 上海市公共数据开放平台中逐项确认使用许可的数据集；
3. 各区政府/统计局区级公报与年鉴，交叉核对定义；
4. 取得可复用授权的地图/地理数据、官方地理信息服务；
5. 其他第三方来源仅作补充候选，不得自动视为允许抓取和再分发。

具体源、链接、状态见 [DATA_CATALOG](./DATA_CATALOG.md)。每条源必须经过 **发现→元数据核验→下载/使用许可核验→可获取性复核→测试解析→采纳**，当前目录中的「候选」不等于已获授权或实际取得数据。

## 5. 功能需求（可测试）

### F-01 地图世界与相机（P0）

- FR-001 上海全域及必要背景可见；鼠标滚轮、拖动、触控缩放、主页复位工作。
- FR-002 地理边界与网格叠合正确；选择格网时可查看 `cell_id`、覆盖状态和允许展示的土地/水域类别。
- FR-003 不同缩放级别控制网格与城市图标密度；相机状态支持 URL hash/查询参数分享。
- FR-004 缺少可用地图数据时，展示明确的数据不可用说明，绝不展示自造行政边界。

### F-02 行政区与搜索（P0）

- FR-010 16区具有唯一稳定标识、中文名称、规范代码；支持中文搜索。
- FR-011 点击区面板显示人口、面积、人口密度、GDP 及可用字段（缺失字段显示「暂无数据」）。
- FR-012 展示数据统计期、单位、来源、区级尺度与可比性说明。
- FR-013 重点功能区按已核验范围或代表点定位，不与行政区错误等同。

### F-03 专题图层（P0）

- FR-020 支持主题切换、图例、实际数据范围、缺失比例、更新时间和来源。
- FR-021 初版目标：人口规模/人口密度、GDP 或经济结构、土地/水体、交通/公共设施中至少4个具备有效数据的图层；如果其中某层条件不满足，需提供合规替代指标并记入变更日志。
- FR-022 默认按指标**真实粒度**着色；图例明确分级/色带算法（线性/分位等）。
- FR-023 视觉颜色不暗示未经证明的价值排序；定量指标保留单位和采样方式。

### F-04 数据百科 Almanac（P0）

- FR-030 每个数据集显示发布者、标题、原始 URL、授权状态、统计年份、下载/构建版本、校验和、处理规则及限制。
- FR-031 每个指标可以反查来源和方法，派生指标展示公式及分母。
- FR-032 数据缺失和不同年份拼接必须明确提示。

### F-05 游戏化语义与美术（P1）

- FR-040 「金融」「科技」「制造」「物流/港口」「文化」等区域徽章需以可验证规则或权威定义产生，说明**区域类型/比较口径**，不代表统计排名。
- FR-041 提供基础地形符号及多级 LOD；动效不能掩盖数据和来源。
- FR-042 如使用「粮食/生产/金币/科学/文化」概念，必须有独立指标映射字典、单位和代理指标警示；没有足够数据时关闭该玩法，而非虚构分数。
- FR-043 使用原创或许可兼容的程序化视觉资产；不得误用游戏公司的受保护素材。

### F-06 Explore / 对比（P0-P1）

- FR-050 MVP 支持在同一指标下比较任意两个区的有效值，提供时间口径提示。
- FR-051 P1 支持16区榜单、散点图、筛选和地图高亮联动。
- FR-052 统计缺失时不能计入排名，也不能被展示为最后一名。

### F-07 分享与可访问性（P0）

- FR-060 可分享的 URL 恢复专题、区选择、基本相机视角，地址栏无个人信息。
- FR-061 支持无鼠标导航到核心控制与区/指标选择；非颜色唯一编码，具有适当对比度与辅助文案。
- FR-062 桌面和移动布局可用，面板在窄屏不遮住必要操作。

## 6. 信息架构与核心画面

```text
ShanghaiCiv
├─ 地图主页
│  ├─ 顶部：全市概况 + 搜索 + 来源入口
│  ├─ 地图：行政区/水域/六边形/图层
│  ├─ 侧栏：行政区或重点区域详情
│  ├─ 图例：单位、色阶、缺失/来源警告
│  └─ 工具：复位、链接分享、图层选择
├─ 区域对比
├─ 数据百科 / Almanac
├─ 帮助与方法论
└─ 开发者数据质量报告（构建产物）
```

交互状态最少包含：`camera`、`selectedDistrict`、`selectedZone`、`selectedCell`、`lens`、`hover`、`layers`、`panel`，同一时间区和区域的选择优先级有明确规则。地图图层只能通过注册接口添加，不能从业务面板直接操纵 Canvas 内部状态。

## 7. 视觉设计规范

**产品观感**：严肃、克制的「策略地图 / 城市图谱」；第一优先级是可读性，不追求高饱和游戏特效。

- 地形：水体、建成区、农田/绿地等类别仅依据可信可用空间数据绘制；无数据时用中性底色。
- 行政区域：区边界清晰、选中态明显；无权限改造官方底图的情况下采用合规叠加方案。
- 城市标签：字号随缩放级别变化，冲突时隐藏次级标签，不遮盖数据图例。
- Canvas 绘制：静态底图缓存 + 动态交互覆盖层；高缩放使用更细节的 LOD，合理的 sprite 缓存和可测性能预算。
- 专题图：必须包含颜色范围、空值样式、单位、统计期与是否估算。
- 设备：优先桌面；兼容移动端触控和底部抽屉面板。
- 品牌：自有标识和字体，不复制《文明》商标和现成视觉资源。

## 8. 技术要求与非功能指标

| 类别 | 要求 |
|---|---|
| 数据架构 | Source adapter → Normalized interim → Spatial builder → validated web/data |
| 静态优先 | 数据编译成可部署的 JSON/压缩静态文件；减少浏览器 GIS 计算 |
| 数据合同 | 明确版本、单位、CRS、null、时间粒度、引用唯一性、数组长度等 |
| 构建可重现 | 固定来源清单、sha256、缓存和确定性排序；支持 --offline |
| 可测试 | Python pytest/unittest、JS 数学一致性测试、Playwright E2E |
| 性能 | 以桌面 45 FPS、移动端 30 FPS 作为**基准环境目标**；必须披露测试设备及地图场景，不能宣称已达标 |
| 体积 | 静态数据包目标初始 ≤ 15 MB（仅为预算，若无法达到需分析并调整）；懒加载扩展数据 |
| 用户安全 | 不收集账户、个人位置历史和可识别行为；链接只存可共享地图状态 |
| 错误处理 | 接口失败/不合规源应 fail closed；前端提供降级和重试说明 |
| 可维护性 | 模块化、类型/合同文档、目录约定、CI 质量门禁 |
| 兼容性 | 最新稳定版桌面 Chrome/Safari/Firefox 和主流手机浏览器，版本按实际测试矩阵报告 |
| 部署 | GitHub Pages；仅在发布许可与地图审核相关检查完成后启用公开发布 |

## 9. 安全、法律与公开地图发布门禁

此 PRD **不是法律意见或已经获得地图审核批准的证明**。发布前必须明确：

- 底图供应商、瓦片/行政边界/河流与其他数据的许可、归属署名、缓存权限与再分发权限；
- 公开页面是否构成需要依法审核的地图/互联网地图服务，以及相应的审核与审图号/更新标注义务；
- 是否允许在受审核地图上绘制自定义六边形覆盖、行政边界及新增 POI；可能需要完成新增标注核查；
- 跨坐标系处理、精细化设施等是否涉及测绘成果、保密、敏感位置限制；
- 统计资料的公开再利用条件及图片/字体/游戏化素材权利；
- 静态数据和源码打包不泄露未获再分发权限的原始数据或 API 凭证。

## 11. 风险清单

| 风险 | 影响 | 应对 / 阻塞条件 |
|---|---|---|
| 行政区几何数据缺少允许再分发的授权 | 无法合法构建公开独立地图 | 优先合法底图叠加；取得授权前不发布衍生边界 |
| 不同统计期不一致 | 排名或比较误导 | 标注年份，默认禁用跨期排名 |
| 区级数据被误读为格网级 | 形成伪精度 | 统计层只在真实统计单元表达，格网 tooltip 标注数据粒度 |
| 功能区边界含糊 | 无法精确点击/统计 | 先点位，边界另行认证 |
| 公开来源撤回或格式变化 | 构建中断 | 缓存、校验、人工审核降级 |
| Canvas 移动端性能不足 | 地图不可用 | LOD、视窗裁剪、sprite cache、性能预算 |
| 数据/服务密钥泄露 | 安全及许可风险 | 权限控制、扫描和静态数据白名单 |
| 科普美术与数据真实性冲突 | 损害可信度 | 美术与观察值分层，强制方法说明 |
